# API-контракт MVP

Базовый префикс: `/api/v1/`. Интерактивная OpenAPI-документация доступна по `/api/docs/`, схема — по `/api/schema/`.

Аутентификация MVP использует Django session cookie. Для изменяющих запросов из браузера frontend должен передавать CSRF-токен и `credentials: "include"`.

## Публичные каталоги

| Метод и путь | Назначение |
| --- | --- |
| `GET /profiles/` | опубликованные публичные профили; фильтры по стране, навыку, языку, формату и доступности |
| `GET /profiles/{slug}/` | публичный профиль |
| `GET /organizations/` | опубликованные публичные организации |
| `GET /organizations/{slug}/` | публичная организация |
| `GET /projects/` | опубликованные проекты с актуальным дедлайном |
| `GET /projects/{slug}/` | проект, роли, навыки, фокусы и публичные контакты |

## Личный кабинет

| Метод и путь | Назначение |
| --- | --- |
| `GET|POST /me/profile/` | прочитать или создать собственный профиль |
| `PATCH /me/profile/` | изменить базовые данные профиля |
| `GET|POST /me/projects/` | список собственных проектов или создание черновика |
| `PATCH /me/projects/{id}/` | изменить собственный проект |
| `POST /me/projects/{id}/roles/` | добавить роль в собственный проект |
| `GET /notifications/` | личные уведомления |
| `POST /notifications/{id}/read/` | пометить своё уведомление прочитанным |

`POST /me/projects/` не требует организации: без `organization` создаётся личный проект текущего пользователя. Если у пользователя уже есть роль `talent`, она сохраняется, а роль `project_lead` добавляется отдельно. В публичном ответе `owner_profile` содержит ссылку на профиль автора только тогда, когда этот профиль опубликован и имеет публичную видимость.

Создание и редактирование организации в первом backend-срезе выполняется через Django Admin. Это намеренное временное ограничение до реализации кабинета организации во frontend.

## Отклики и модерация

| Метод и путь | Право |
| --- | --- |
| `POST /project-roles/{id}/applications/` | авторизованный пользователь с опубликованным public-профилем |
| `PATCH /applications/{id}/transition/` | владелец проекта; только допустимые переходы state machine |
| `POST /moderation/submit/` | владелец профиля/проекта/медиа или уполномоченный представитель организации |
| `GET /moderation/cases/` | модератор или администратор |
| `PATCH /moderation/cases/{id}/decision/` | модератор или администратор |

`POST /moderation/submit/` принимает `{ "target_type", "target_id", "reason_code" }`, где `target_type` — `profile`, `organization`, `project` или `media`. Решение принимает `{ "decision", "note" }`; допустимые решения: `approved`, `changes_requested`, `rejected`.

Решение меняет публикационный статус цели, создаёт `AuditEvent` и записывает `OutboxEvent`. Worker Celery доставляет его как пользовательское уведомление.
