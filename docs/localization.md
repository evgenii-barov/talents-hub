# Локализация frontend

Локализация сосредоточена в `frontend/components/i18n` и имеет единый fallback на
английский язык.

## Добавление локали

1. Добавить BCP 47-код и метаданные в `locales.ts`.
2. Добавить полный именованный словарь в `messages.ts`. TypeScript проверит, что
   в нём есть все ключи интерфейса.
3. Для новых строк использовать `t("messageKey")` и добавлять ключ во все
   словари.
4. Для локализованных данных, которые не являются строками интерфейса,
   использовать `localize({ en: fallbackValue, ...translations })`.

После добавления локали старые экраны продолжат работать с английским fallback,
даже если их перевод ещё не готов.

## Совместимость со старым кодом

Двухаргументный вызов `tr(english, russian)` сохранён как временный адаптер для
существующих экранов. Новый код должен использовать именованные ключи либо
форму `tr({ en: "...", ru: "...", "zh-Hans": "..." })`.

Китайская локаль использует код `zh-Hans`, форматирование `zh-CN` и подпись
`简体中文`. Бизнес-код языка в таксономии (`zh`) от локали интерфейса не зависит.

Китайские переводы старых экранов разбиты по доменам в
`frontend/components/i18n/catalogs/zh-hans`. Команда `npm run i18n:check`
проверяет, что новые статические строки, динамические сообщения и локализованные
значения не были добавлены без китайского варианта.
